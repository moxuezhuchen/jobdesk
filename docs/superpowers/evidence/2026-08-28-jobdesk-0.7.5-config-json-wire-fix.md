# JobDesk 0.7.5 configuration JSON-wire fix-forward evidence

This candidate is based on released JobDesk `v0.7.4` at
`b094bc9119354e30b96b6f60648f8ae45c55b80e`. It does not modify ConfFlow,
the configured production endpoint, or any scientific workload.

The stopped `v0.7.4` side-by-side acceptance proved that configuration
admission sent the public YAML bytes directly to the formally released
ConfFlow `v2.1.6` command `config validate --json --stdin`. The producer owns
that stdin ABI and requires a JSON object. Repeated non-compute probes showed:

- `wc -c` received all 328 input bytes through `SSHClientWrapper.run`;
- 20 wrapper calls and five raw Paramiko calls returned the same exit `1`,
  empty stdout, and `Error: invalid JSON input: Expecting value` stderr;
- therefore neither stdin transport nor stdout draining lost data.

JobDesk `0.7.5` keeps YAML at its public consumer boundary, parses it once,
and sends producer-canonical JSON bytes to the remote v1 validation command.
Malformed UTF-8/YAML and YAML values outside the producer JSON wire domain
fail closed before remote validation. The exact approved ConfFlow `2.0.0`
stable fallback retains its historical YAML validator input.

The corrected non-compute SSH probe against the installed formal ConfFlow
`v2.1.6` wheel produced structured stdout with exit `0` for the accepted
document and exit `1` for the rejected document. End-to-end
`RunCoordinator.admit_configuration` succeeded without creating a run or
dispatching a launcher. The evidence is retained outside the repository at
`C:\tmp\jobdesk-v074-confflow-v216-real-launcher-20260828-034516-a96ee402\evidence\jobdesk-075-ssh-fix-probe.json`.

This candidate is not merged, tagged, released, promoted, or authorized for
production use.
